0001 — pi-tui 架构全景与核心原理

层级：L3 微观 API 预计时长：12 分钟 学习目标：1 个

学习目标：确认 pi-tui 可独立嵌入任意 Node.js 项目，理解其三层架构（Terminal → TUI → Components）和差分渲染核心原理。

1. 能独立用吗？——零 Pi 依赖确认

可以。@earendil-works/pi-tui 是一个完全独立的 npm 包。打开它的 package.json，你只会看到两个外部依赖：

  • get-east-asian-width — 判断 Unicode 字符的东亚宽度（全角 2 列 / 半角 1 列）
  • marked — Markdown 解析器，仅 Markdown 组件使用

它不依赖 pi-agent-core、pi-ai 或 Pi monorepo 中任何其他包。这意味着你可以在自己的 CLI 工具中 npm install @earendil-works/pi-tui 然后直接使用，无需引入整个 Pi 生态。 

你的项目
  └── @earendil-works/pi-tui  (零 Pi 依赖)
        ├── get-east-asian-width
        └── marked

2. 三层架构：Terminal → TUI → Components

pi-tui 采用清晰的三层架构，每一层职责分明：

层级核心类/接口职责
传输层 Terminal 接口 + ProcessTerminal 封装 stdin/stdout，管理 raw mode、resize 事件、ANSI 序列写入、键盘协议协商
渲染引擎层 TUI 类（继承 Container） 组件树管理、输入路由、差分渲染算法、Overlay 栈、焦点管理
组件层 Component 接口 + 13 个内置组件 每个组件实现 render(width) → string[]，由 TUI 收集后统一输出

数据流方向：用户按键 → Terminal 读取 → TUI 路由给焦点组件 → 组件更新状态 → TUI 收集 render() 结果 → 差分比对 → Terminal 写入 ANSI 序列。

3. Component 接口契约

所有组件只需实现一个核心接口，极其简洁：

export interface Component {
  render(width: number): string[];  // 必须：返回定长行数组
  handleInput?(data: string): void; // 可选：获得焦点时处理按键
  invalidate(): void;               // 必须：清除缓存，触发重绘
}

关键约束：render() 返回的每一行必须 visibleWidth(line) ≤ width，否则 TUI 会抛出崩溃保护异常。组件内部应使用 truncateToWidth() 截断超长行。

组件可通过实现 Focusable 接口（含 focused: boolean 属性）来获得硬件光标定位支持，使 IME 输入法候选窗出现在正确位置。

4. 差分渲染原理（一分钟速览）

差分渲染是 pi-tui 无闪烁体验的核心。它不每次清屏重绘，而是：

  1. 保存上一帧：previousLines: string[] 记录上次渲染的每一行
  2. 逐行比对：找出 firstChanged 和 lastChanged
  3. 只发送变化区域：用 ANSI 光标移动序列跳到变化行，只重写变化部分
  4. 同步输出包裹：用 CSI 2026（\x1b[?2026h / \x1b[?2026l）包裹所有输出，终端在收到结束符后才一次性刷新，消除撕裂

三种渲染策略：首帧（直接输出，不清屏）、全量重绘（窗口尺寸变化或内容收缩时触发）、增量渲染（默认，只写变化行）。

⚠️ 注意：只有当内容高度超过终端可视行数时，终端才会滚动。如果你的 TUI 应用内容很少，用户看不到滚动效果是正常的——差异渲染在少量内容时表现为就地更新。
