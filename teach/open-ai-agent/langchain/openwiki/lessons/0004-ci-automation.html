第四课：CI/CD 自动化文档更新

学习目标：配置 GitHub Actions 实现文档的定时自动更新，理解 CI 中 OpenWiki 的运行模式。

1. GitHub Actions 工作流详解

代码天天在变，文档如果只靠手动 --update 很快就会过时。--init 已自动生成 CI 配置文件 .github/workflows/openwiki-update.yml：

name: OpenWiki Update
on:
  workflow_dispatch:          # 可手动触发
  schedule:
    - cron: "0 8 * * *"      # 每天早上 8 点运行
permissions:
  contents: write
  pull-requests: write
jobs:
  update:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: "22" }
      - run: npm install --global openwiki
      - run: openwiki code --update --print
        env:
          OPENWIKI_PROVIDER: openrouter
          OPENROUTER_API_KEY: ${{ secrets.OPENROUTER_API_KEY }}
      - uses: peter-evans/create-pull-request@v7
        with:
          add-paths: |
            openwiki
            AGENTS.md
            CLAUDE.md
            .github/workflows/openwiki-update.yml
          branch: openwiki/update
          commit-message: "docs: update OpenWiki"
          title: "docs: update OpenWiki"
🔑 关键环境变量： CI 中通过 OPENWIKI_PROVIDER 和 OPENROUTER_API_KEY（或其他提供商的 Key）配置 AI 提供商。这些值应存入 GitHub Secrets。

为什么必须用 --print？

工作流中使用 openwiki code --update --print 而非纯 --update：

交互模式--print 模式
适用环境本地终端CI/脚本
执行后保持会话等待输入输出结果后退出
输出终端 UI纯文本结果

CI 没有交互式终端，不带 --print 的 openwiki 会尝试启动 Ink UI 从而报错。

其他 CI 平台

官方提供了三个平台的模板，位于 examples/ 目录：

💡 多提供商配置： CI 环境变量可以配置不同于本地的提供商。例如本地用 OpenAI，CI 用 OpenRouter，互不干扰。

2. 练习：配置 CI 自动化

📝 动手练习

  1. 查看你仓库下的 .github/workflows/openwiki-update.yml
  2. 在 GitHub 仓库 Settings → Secrets and variables → Actions 中添加：OPENROUTER_API_KEY
  3. 手动触发工作流：GitHub → Actions → OpenWiki Update → Run workflow
  4. 工作流完成后，查看自动创建的 PR
  5. （选做）将定时改为每周一早上 9 点：0 9 * * 1

思考题： 为什么工作流用 --print 而不是不带参数？不用 --print 会发生什么？

提示：CI 没有交互式终端。不带 --print 的 openwiki 会尝试启动 Ink UI，在非 TTY 环境会报错。

回顾要点

  • --init 自动生成 GitHub Actions 工作流
  • CI 中必须用 --print 实现非交互式运行
  • API Key 通过 GitHub Secrets 注入环境变量
  • 文档更新通过 PR 流程审查，安全可控
