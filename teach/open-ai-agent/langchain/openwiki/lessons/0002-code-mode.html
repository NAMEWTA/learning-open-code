第二课：代码模式深入——更新文档与日常使用

学习目标：掌握 openwiki --update 的增量更新机制，以及如何通过交互式聊天精细化控制文档内容。

1. 增量更新与运行模式

代码不会一成不变，文档也需要同步更新。--update 是日常最常用的命令：

openwiki --update

与 --init 的区别：

特性--init--update
用途首次生成增量更新已有文档
覆盖行为全新生成在已有内容上补充/修订
CI 中是否需要不需要会自动创建不存在的文档
💡 CI 关键点： GitHub Actions 等 CI 环境中只需 --update，无需先跑 --init。

带提示的更新

你可以给 OpenWiki Agent 附加额外指令，让它关注特定方面：

openwiki --update "请先记录所有 API 端点"
openwiki --update --modelId gemini-3.5-flash "用中文生成文档"

这会在更新时把提示作为额外上下文传给 Agent。

单次运行模式：-p / --print

如果不想进入交互式会话，只想让 OpenWiki 执行一次并输出结果后退出：

openwiki -p "总结这个仓库能做什么"
openwiki --update --print

这在 CI 脚本和自动化管线中特别有用。

2. Agent 指令体系

初始化后，仓库根目录多了 AGENTS.md 和 CLAUDE.md。OpenWiki 会在其中维护一个 <!-- OPENWIKI:START --> 区块：

<!-- OPENWIKI:START -->

## OpenWiki

This repository uses OpenWiki for recurring code documentation.
Start with `openwiki/quickstart.md`, then follow its links to
architecture, workflows, domain concepts, operations, integrations,
testing guidance, and source maps.

<!-- OPENWIKI:END -->

作用链：

  1. OpenWiki 在 AGENTS.md/CLAUDE.md 中注入提示
  2. 编码 Agent（如 GitHub Copilot、Claude Code）读取这些文件
  3. Agent 知道去 openwiki/quickstart.md 寻找上下文
  4. Agent 在回答问题时就能引用最新的 Wiki 文档

OpenWiki 只修改 <!-- OPENWIKI:START --> 和 <!-- OPENWIKI:END --> 之间的内容，不会覆盖你自定义的其他内容。

自定义指令：openwiki/INSTRUCTIONS.md

这个文件是你写给 Agent 看的，用于控制文档的范围和重点：

# 仓库 Wiki 指令

## 范围
- 重点记录核心业务逻辑和 API
- 忽略测试代码和第三方依赖
- 为每个模块生成一个独立的页面

## 优先级
1. API 文档
2. 数据模型
3. 部署配置

OpenWiki 在每次 init/update 时会读取 INSTRUCTIONS.md，它不会自动修改此文件（除非你明确要求）。

3. 练习：更新并自定义

📝 动手练习

  1. 在已初始化的仓库中运行 openwiki --update "请补充测试部分的文档"
  2. 打开 openwiki/INSTRUCTIONS.md，添加一条指令：优先使用中文生成文档
  3. 再次运行 openwiki --update，观察文档风格变化
  4. 查看 AGENTS.md 中的 OPENWIKI 区块是否存在

思考题： 如果 INSTRUCTIONS.md 和 --update 的附加消息冲突了，Agent 会优先听谁的？

提示：内联消息优先级高于持久指令。

回顾要点

  • --update 是日常增量更新命令，CI 中无需先 --init
  • -p / --print 用于单次非交互式运行
  • Agent 指令文件让编码助手自动感知 Wiki 文档
  • INSTRUCTIONS.md 是用户控制文档方向的"遥控器"
