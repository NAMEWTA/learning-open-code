提示词审计字段与排障清单

用于配置 Guard 节点、核对运行态，以及定位“为什么没记录用户问题”。

返回 15 分钟照做版

上线前提

  • PostgreSQL 正常：最终事件和未脱敏完整提示词写在 prompt_audit_events。
  • Redis 正常：异步审计用它保存队列和临时 payload；临时 payload 处理后删除，事件仍留在数据库。
  • 服务设置固定的 TOTP_ENCRYPTION_KEY：用于持久化加密 Guard API Key。
  • Guard 服务可从 sub2api-plus 后端所在网络访问，而不是只从你的浏览器访问。

节点字段怎么填

节点名称
便于管理员识别，如 Qwen3Guard 主节点。
稳定节点 ID
填写长期不变的英文 ID，如 guard-primary。
Base URL
填 https://guard.example.com 或带必要前缀的根路径。系统自动请求 /v1/chat/completions，不要填写完整接口路径。
API Key
Guard 服务要求鉴权时填写；请求会使用 Authorization: Bearer ...。
模型
必须是能返回 Qwen3Guard 文本协议的模型。页面默认值为 sileader/qwen3guard:0.6b；按本文自建 vLLM 时改为 Qwen/Qwen3Guard-Gen-0.6B。
总超时
范围 100–30000 ms。冷启动或 CPU 推理可先用 10000–30000 ms，稳定后再降低。
单片上限
默认 4000 个 Unicode 字符；长提示词会分片审计，不等于完整提示词的数据库长度上限。
启用节点
必须开启；至少有一个已启用节点才能启用提示词审计。

没有 Guard 服务时自建

在一台受支持的 GPU 服务器上安装 vLLM，并启动 Qwen 官方的生成式 Guard。它是独立服务，不要装进正在处理业务流量的 sub2api-plus 容器：

python3 -m venv .venv
source .venv/bin/activate
pip install -U "vllm>=0.9.0"
vllm serve Qwen/Qwen3Guard-Gen-0.6B \
  --host 0.0.0.0 \
  --port 8000 \
  --max-model-len 32768

然后在 sub2api-plus 节点中填：Base URL 为 http://Guard服务器地址:8000，模型为 Qwen/Qwen3Guard-Gen-0.6B。默认 vLLM 未配置鉴权时 API Key 可留空；生产环境应通过内网、防火墙或带鉴权的网关限制访问。官方依据见 Qwen3Guard 仓库与 0.6B 模型卡。

Guard 接口契约

sub2api-plus 会发送近似下面的请求。你可以从与后端相同的网络环境手工测试：

curl -sS https://guard.example.com/v1/chat/completions \
  -H 'Authorization: Bearer YOUR_GUARD_KEY' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "Qwen/Qwen3Guard-Gen-0.6B",
    "messages": [{"role": "user", "content": "hello"}],
    "temperature": 0,
    "max_tokens": 64,
    "seed": 42
  }'

返回体必须是 OpenAI 兼容结构，并让 choices[0].message.content 至少包含一次 Safety: 和 Categories:。安全结果示例：

{
  "choices": [{
    "message": {
      "content": "Safety: Safe\nCategories: None"
    }
  }]
}

推荐的首次配置

适用范围
全部分组。若选指定分组，未选中的用户请求不会记录。
风险分类
九类全部开启。至少要启用一类。
Worker / 队列
先用默认 4 / 32768；根据积压和机器资源调整。
启用提示词审计
开启。
同步阻止
首次关闭。异步模式不会因 Guard 故障阻断用户。
保存安全事件
开启。这是保存所有正常提示词的关键。

错误对照

事件里只有风险提示词，没有正常问题

开启“保存安全事件”并保存，确认页面显示“配置已同步”。

页面看似开启，生效模式仍是已关闭

检查系统设置中的“启用风控中心”总开关、提示词审计自身开关，以及是否至少有一个启用节点。

invalid_response

接口可能接入了普通聊天模型，或输出缺少 Safety/Categories。检查模型 ID 和实际响应内容。

404

通常是 Base URL 填成了完整接口，导致路径重复。改填服务根地址。

401 / 403

检查 Guard API Key、模型访问权限和服务重启后凭据状态。若提示无法解密，重新设置固定 TOTP_ENCRYPTION_KEY 并录入 Key。

超时或节点不可用

确认网络地址从后端可达；Docker 中不要误用宿主机的 127.0.0.1；适当提高超时并等待模型冷启动完成。

处理数不增加

检查 Redis、分组范围、提取成功计数和队列丢弃数。未知协议或没有可提取用户文本的请求可能不会产生事件。

究竟记录什么

异步 Prompt Audit 记录本次请求中由用户编写的提示词，包括常见 Chat、Responses、Gemini、搜索查询、Embedding 字符串和图片生成提示词等已适配文本。它排除 system/developer 指令、模型回复、reasoning、工具定义、工具参数和工具结果。未知结构可能无法提取，因此这里的“所有”是“所有已被项目适配并成功提取的用户提示词”，不是原始 HTTP Body 的无条件镜像。

事件详情中的“完整提示词（未脱敏）”是你要看的字段。普通业务模型响应不会保存；Guard 只保留归一化后的判定、分类、分数和脱敏证据，不保存 Guard 原始响应体。

数据保留

完整提示词可能包含密码、个人信息、商业秘密或代码。只授予必要管理员访问权限，并在隐私政策中明确告知。当前实现提供选中删除和按筛选删除；未发现 Prompt Audit 自动保留天数设置，建议固定周期按时间筛选预览后删除。
