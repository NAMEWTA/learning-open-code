## 功能说明

`writing-for-agents` 是你在写面向 Agent 的文档时对照的参考——一个技能、一份 `AGENTS.md` / `CLAUDE.md`、一份[规格](https://www.aihero.dev/ai-coding-dictionary/spec)、一个运行时提示词、一个 README,任何[Agent](https://www.aihero.dev/ai-coding-dictionary/agent) 会读的文档。包装不同,写法不变:同样的杠杆让每一份都变得可预测,于是 Agent 每次运行走的是同一个*过程*,而不是产出同一份输出。

它的默认动作是删除,不是解释。让一个 Agent 写给另一个 Agent 的指令,它会把大部分篇幅花在解释[模型](https://www.aihero.dev/ai-coding-dictionary/model)已经知道的东西上——这些行每一行都是**空操作**,支付[上下文](https://www.aihero.dev/ai-coding-dictionary/context)却不改变任何行为。这份参考就是找出它们的透镜,这也是为什么它在已有的文档上至少和空白文件上一样频繁地挣回自己的价值。

它直到 v1.1 都叫 `writing-great-skills`。改名追认了它底下一直以来的真相:几乎没有任何部分是技能特有的。纯技能机制——frontmatter、模型调用与用户调用之分、路由技能——披露在一份链接的 `SKILL-MECHANICS.md` 里,只有当你面前的文件是技能时才需要读。

## 何时使用

输入 `/writing-for-agents`,或者当你在创建或编辑技能、修改 `AGENTS.md` 或 `CLAUDE.md` 时,Agent 会自己调用它。

其他一切 Agent 会读的东西都手动用它:你的文档、规格和[工单](https://www.aihero.dev/ai-coding-dictionary/ticket)、系统提示词和 [AFK](https://www.aihero.dev/ai-coding-dictionary/afk) 提示词。测试只有一个问题——Agent 会读这个吗?——而且它怎么到 Agent 面前并不重要:是指针点名了它、人把它粘贴进去,还是它只是躺在仓库里。要想先弄清一个代码库里到底有什么,用 [grill-with-docs](https://aihero.dev/skills-grill-with-docs)——这份参考管的是文档读起来怎么样,不是它知道什么。

## 两种负担

整份参考围绕的是一对每个文档和指针都在花的预算:

- **上下文负担**——常驻加载的材料对 Agent 窗口的代价:`AGENTS.md` 的一行、一个技能描述,任何每个[回合](https://www.aihero.dev/ai-coding-dictionary/turn)都待在上下文里、不管它是否触发的东西。
- **认知负担**——落在你身上的代价:哪些文档存在,什么时候该拿哪一份。你就是索引。这不是一个要最小化的成本——它是人类主体的代价。

一旦用这两种负担思考,大多数写作决策——拆分还是不拆、内联还是披露、指向还是推送——就变成在别处做的同一种权衡。

## 杠杆

- **[上下文指针](https://www.aihero.dev/ai-coding-dictionary/context-pointer)**——放在上下文里、点名上下文之外的材料并编码何时去取它的参考。一个技能描述和一行点名某文档的 `AGENTS.md` 是同一个对象;决定 Agent 是否可靠地透过它取到东西的,是指针的*措辞*,不是它的目标。
- **信息层级**——从文件内步骤、到文件内参考、再到指针后面的披露参考的阶梯。**[渐进式披露](https://www.aihero.dev/ai-coding-dictionary/progressive-disclosure)** 是沿着阶梯往下走,好让顶层保持可读。
- **完成标准**——每个步骤完成条件的清晰度和要求,以及这个要求驱动的**跑腿功夫**;这是对**过早完成**的防线。
- **引导词**——一个已在模型预训练里的紧凑概念(*tight*、*red*、*tracer bullet*),Agent 在运行文档时用它思考。它锚定两处:正文里的执行,指针里的调用。
- **修剪**——单一事实来源、相关性,以及逐句应用的空操作测试,对着**重复**、**沉淀**和**蔓延**。

## 常见问题

**`/writing-great-skills` 去哪了?**
就是这个技能,v1.1 改的名。从业者早就把它指向 `AGENTS.md`、文档、规格、工单和运行时提示词,远在名字跟上之前;结构、引导词和修剪结果就是任何 Agent 会读的文本的手艺。没有别名——在新名字下重新安装。

**「为 Agent 写作」——所以是 Agent 来写?**
反了。你是作者;Agent 是读者。这正是这种文体的全部难处:你是在为一个已经读过一切的人写作,所以解释是浪费,精确是整个工作。

**我不能直接让 Agent 替我写吗?**
可以,而且它会产出啰嗦的东西。没人管的时候,模型会解释它已经知道的事,它不会自己应用空操作测试,也不会主动找引导词。把参考用在草稿上——审阅一遍正是它大部分价值的落点。

**我让 Agent 精简文档,它把功能删了。**
被告知「精简」的 Agent 会朝长度优化,因为长度是它们看得见的东西。空操作测试是行为性的,不是审美性的:删掉这行,问 Agent 的行为变没变。当一句失败时,删掉整句而不是从中删词——而且争论不下时,用跑一遍文档来解决,而不是靠吵架。

**我怎么知道它完成了?**
当它有效,而且你再也找不到重复、沉淀和空操作时。这里没有自动化评估;检查手段是手动跑一遍,加上把失败模式词汇表当诊断工具。当文档行为异常时,这个词汇表也是修理包——先命名失败模式,再修它。

**这该放进 `CLAUDE.md` 还是别的地方?**
问你想付哪种负担。`CLAUDE.md` 无条件加载进每个[会话](https://www.aihero.dev/ai-coding-dictionary/session);指针后面的材料在触发之前只花指针自己那一行的代价。任何十个上下文里只适用一个的东西,另外九次都在付上下文负担。

**我需要对每个新模型重写文档吗?**
大多不必,而且对单一模型过拟合本身是个陷阱。为新模型更新通常又是一轮空操作通过,而不是重写。

**我的技能只在它建立时那个确切任务上有效。**
常见路径——把活干一遍,然后让 Agent 把它写成技能——对那一次运行过度加权,范例出来过于具体。把那次运行留作证据,然后刻意抽象:剥掉属于那个仓库那些文件的东西,为任务的类别而写。

**英语不是我的母语。我会失去引导词优势吗?**
不会——找到把最多行为塞进最少 [token](https://www.aihero.dev/ai-coding-dictionary/token) 的那个词,是参考替你做的活。这正是它的用途之一。

## 效果如何判断

- 文档越好越短,而且你惊讶于剩得这么少。
- 你能指着一个引导词,看着它在不止一处起作用。
- 没有任何东西以任何形式被说过两遍。重复是最可靠的信号,说明一份文档从未被测试过。
- 只有某个分支才需要的参考,待在指针后面,而不是主文件里。

## 在系统中的位置

这是一份随时可用的独立参考。它在链条里没有邻居,因为它坐在整套东西的底下,而不是任何单个技能旁边:这里的每个技能都是照着它写的,而其他技能留下的文档——一份 `CONTEXT.md` 和它的 ADR、一份规格、一张工单——一旦 Agent 必须读它们,正是它管辖的文本。不确定哪个技能或流程适合任务时,[ask-matt](https://aihero.dev/skills-ask-matt) 会在整套里为你导航。
