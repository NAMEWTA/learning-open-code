## 功能说明

`handoff` 把当前对话压缩成一份**交接文档**——一个 Markdown 文件,写到操作系统的临时目录而不是工作区里——新开的 [Agent](https://www.aihero.dev/ai-coding-dictionary/agent) 读完它就能把工作接过去。

它买到的是**可携带性**,不是压缩。这让这个技能比听上去窄。只有当工作必须*迁移*时——到一个新的[宿主环境](https://www.aihero.dev/ai-coding-dictionary/harness)、新目录、交给同事、或者一个你想分叉出去的支线任务——你才需要文件。如果没有东西在迁移,你就不需要交接:留在[会话](https://www.aihero.dev/ai-coding-dictionary/session)里、`/clear`、[子 Agent](https://www.aihero.dev/ai-coding-dictionary/subagent) 和 `/compact` 就能覆盖常规的阶段收尾,而且 `/compact` 用得比这个技能还多。

## 何时使用

你通过输入 `/handoff` 来调用它——Agent 不会自己主动使用。给它一句关于下一个会话要干什么的说明,文档就照着这个写。

触发它的只有四种情形:

| 情形 | 为什么要文件 |
| --- | --- |
| 换宿主环境——Claude → Codex | 新宿主看不到旧的[上下文](https://www.aihero.dev/ai-coding-dictionary/context) |
| 移到另一个目录或仓库 | 原型目录是最常见的情况 |
| 把工作交给同事 | 他们需要能读的东西 |
| 分叉一个阶段中途发现的支线任务 | 你继续干,第二个 Agent 接走分叉 |

除此之外的一切——同一宿主、同一目录、你已经[问询](https://www.aihero.dev/ai-coding-dictionary/grilling)完准备进入实现——用 `/compact` 就对了。在阶段边界上,[ask-matt](https://aihero.dev/skills-ask-matt) 把五个选项的先后顺序树都带着。

## 分叉才是人们跳过的用法

这个技能的描述读起来像是会话恢复:写个摘要,这里结束,那里继续。按这个读法,它像是个更差的 `/compact`,于是被一带而过。分叉用例才值得了解。你**留在自己的会话里**,把累积上下文的一份副本交给一个并行工作的第二个 Agent。

这正是 [prototype](https://aihero.dev/skills-prototype) 绕道用它做的事。你深陷一场设计对话,遇到一个只有跑起来才能回答的问题,又不想把自己辛苦建立的线索花在查证上。交接给一个原型会话,拿到答案,把答案交回来,在原线索里引用它。两次跨接,一条活着的对话,什么都不用重讲。

阶段边界的五个选项里,有三个保存的东西不同:`/compact` 保存你的意图,`/clear` 什么都不保存,`/handoff` 保存工作迁移的能力。

## 什么跟着走,什么不跟着走

文档携带的是活线索——进行中的事、为什么、接下来是什么——外加一节**建议技能**,点名下一个 Agent 该用什么。秘密会在写盘之前被隐去。

它刻意不带任何已经写下来的东西。规格、计划、ADR、issue、提交和 diff 都只以路径或 URL 引用,绝不复制。这让文件保持小巧,也让已定稿的细节留在唯一的地方,而不是分处两处、逐渐漂移。

## 常见问题

**交接还是压缩?**
没有东西在迁移就用 `/compact`。停留在同一个任务上,这是压缩,不是交接——同一宿主、同一目录、需要保持跟进,这正是阶段边界树大多数日子里落下的位置。`/handoff` 的优势不在于摘要写得更好,而在于结果是一个可以带到 `/compact` 到不了的地方的文件。

**那 compact、clear 和 handoff 到底有什么区别?**
保存的东西不同。`/compact` 压缩当前上下文,让你在新窗口里继续——意图得以幸存。`/clear` 清空窗口,从零开始——当你身后的一切都可丢弃时它是正确的选择,如果不可丢弃,它就是单向的。`/handoff` 写出一份可携带的文件——工作能在迁移到别处时幸存。注意,三者都会把**[一手资料](https://www.aihero.dev/ai-coding-dictionary/primary-source)**(发生过的对话)变成**[二手资料](https://www.aihero.dev/ai-coding-dictionary/secondary-source)**(对话的摘要)。只有「继续」不是,这也是为什么它是第一个要排除掉的选项。

**我的交接文件去哪了?**
临时目录,这是这个技能被抱怨最多的摩擦点:路径长、每个操作系统不同,在 Windows 上 Agent 有时要试好几次才能找对。走之前让它把路径说出来并记下来。放临时目录是刻意的:交接文档是过境文件,不是你要维护的成品。它也不是持久文件——见下一个问题。

**我的交接在会话之间消失了。**
有些环境会在会话之间清理临时目录——报告过的是 Codex——`/private/tmp` 在重启后也会清空。如果下一个会话不是在一小时内开始,或者会在另一个宿主下开始,文件一写好就自己把它复制到持久的地方。文档*指向*的东西也一样:一份引用临时目录里其他文件的交接,是下一个 Agent 无法执行的交接。

**我怎么真的把它交给下一个 Agent?**
打开新会话,把路径指给它:读这个文件,然后继续。指文件,而不是把摘要粘贴进 shell 命令——包含反引号或 `$(...)` 的摘要被插值进 `claude "<summary>"` 时会被破坏,常见的失败是无声截断而不是报错,于是新 Agent 拿到一份悄悄残缺的简报。

**这和 `/branch`、`--fork-session` 或内置的 `/handoff` 是一回事吗?**
类似,但不相同,而且这里没有提供 `/branch` 技能——`/handoff` 才是规范名。分叉继承上下文的精确副本;这个技能产出的是一份*针对性的*压缩,瞄准你说明的下一个任务,放在文件里。当分叉能做到时——同一台机器、同一宿主、同一目录——分叉更省事。当目的地是分叉到不了的地方时,文件胜出。

**什么情况下东西该放进 `CLAUDE.md` 而不是这里?**
问一句:下个月它还成立吗?`CLAUDE.md` 是关于项目的常驻上下文,不管相不相关都会加载进每个会话。交接只关于一件进行中的工作,工作落地就失效了。总在被重复解释的事实是 `CLAUDE.md` 的问题;半途而废的任务才是交接。

**它记下了「是什么」,没记「为什么」。**
这是公平且反复出现的批评。两件事有帮助。把论据传进去——告诉它下一个会话是干什么的——这样与之相关的推理会被保留,而不是被压平。另外要警惕会话从未真正验证过的自信断言:「X 还没建」、「Y 已完成」。下一个 Agent 会把文档当契约,不会复核,所以写成事实的信念会成为后续一切的错误前提。交出之前读一遍文档,把你只是假设的内容降级。

**为什么做成技能而不是斜杠命令?**
两者都行,适合不同情形。作为技能,它和其他东西一样通过同一安装路径发布和更新,这正是它可分享的原因——「Agent 不会自己触发它」这个约束由 frontmatter 设定,而不是由机制设定。

## 效果如何判断

- 文档只占对话的一小部分,规格、issue 和 diff 以路径和 URL 出现,而不是复制成文本。
- 不打开原会话,你也能直接读懂它,并知道接下来该做什么。
- 新 Agent 直接开始干活,而不是让你重新解释背景。
- 在分叉场景里,你回来时原会话还还原封不动地待在那里。
- 建议技能一节点名的,正是你自己会伸手去用的那个技能。
- 里面没有任何密钥、token 或密码。

## 在系统中的位置

`handoff` 是一个**随时可用的独立工具**,活在会话之间的接缝处,而不是构建链里——但它很窄,诚实的说法是,阶段边界上的五个选项里,你会用得最少的是它。它最近的邻居是 [prototype](https://aihero.dev/skills-prototype),因为原型住在自己的目录里,出去再回来的往返正是这个技能服务的跨越。当你站在边界上、不确定该继续、清空、交接、委派还是压缩时,[ask-matt](https://aihero.dev/skills-ask-matt) 带着排序这五者的树——并在其余整套技能里为你导航。
