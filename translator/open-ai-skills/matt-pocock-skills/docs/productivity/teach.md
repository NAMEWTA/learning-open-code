## 功能说明

`teach` 把你运行它的目录变成一个常驻教学工作区,用短小的自包含 HTML 课程,跨多次[会话](https://www.aihero.dev/ai-coding-dictionary/session)教给你一个主题。

它不是从[模型](https://www.aihero.dev/ai-coding-dictionary/model)已有的知识来教。[参数化知识](https://www.aihero.dev/ai-coding-dictionary/parametric-knowledge)被视为不可信:开讲之前,它会去找到高可信度的资源,记录进 `RESOURCES.md`,并在每节课里引用它们。另一个结构性事实是它[有状态](https://www.aihero.dev/ai-coding-dictionary/stateful)——使命、资源、课程和你学过什么的记录都作为文件存在目录里,所以下一场会话从这些文件继续,而不是依赖上一场对话残留的东西。

## 何时使用

你通过输入 `/teach` 来调用它——[Agent](https://www.aihero.dev/ai-coding-dictionary/agent) 不会自己主动使用。

当学习本身就是项目时用它:一门语言、一个框架、一个你刚加入的代码库、瑜伽、着色器、一张证书。它不是为顺带讲一次而准备的工具。

| 你想要的 | 该用什么 |
| --- | --- |
| 花几周学一个主题,会话不断积累 | `teach` |
| 在当前会话里顺带讲清一个概念 | 就在那个会话里直接问 |
| Agent 上一条消息没讲明白,要换个说法 | [wait-what](https://aihero.dev/skills-wait-what) |
| 磨利已有的思考,而不是获取新内容 | [grill-me](https://aihero.dev/skills-grill-me) |
| 一个后台 Agent 读[一手资料](https://www.aihero.dev/ai-coding-dictionary/primary-source)并留给你一份带引用的文档 | [research](https://aihero.dev/skills-research) |
| 学习问询中途冒出来的东西,又不打断[问询](https://www.aihero.dev/ai-coding-dictionary/grilling) | [handoff](https://aihero.dev/skills-handoff) 到教学工作区,然后在那边用 `teach` |

## 前置条件

`teach` 构建的是一个目录而不是产出单个文件,而且技能假定一个工作区一个使命——所以把它跑在你愿意整个让给一个主题的地方。别放在你正在工作的项目里:独立仓库是推荐的家,而不是全局的 `~/.learnings/` 文件夹或当前项目本身。独立仓库还能让课程可提交,这也是团队共享它们的方式。

那个目录里会积累什么:

| 路径 | 存放内容 |
| --- | --- |
| `MISSION.md` | 你为什么要学这个。一切都挂在它上面;如果它缺失,`teach` 做的第一件事就是盘问你,直到它存在 |
| `RESOURCES.md` | 经过筛选的教学来源,分为知识(Knowledge)和智慧(Wisdom,社群) |
| `lessons/*.html` | 编号课程——教学的主要单元 |
| `reference/*.html` | 压缩的速查表、算法、词汇表:你真正会回头翻的文档 |
| `learning-records/*.md` | 关于你确已学会内容的 ADR 式记录,用于决定接下来教什么 |
| `assets/*` | 可复用组件——首先是共享样式表——让课程看起来像一门课 |
| `NOTES.md` | 你声明的教学偏好 |

对这个列表有两点诚实的说明。词汇表适合大多数主题,但技能附带了一份 `GLOSSARY-FORMAT.md`,`SKILL.md` 已经不再链接它,所以只有你主动要才会有([issue #559](https://github.com/mattpocock/skills/issues/559))。另外,工作区不一定建在你预期的地方——在它上面搭长课程之前,先看下面第一个问题。

## 存储强度,而不是流利度

值得用来思考的词是**存储强度**:长期记忆,与之相对的是**流利度**,即当下回忆的顺畅感——阅读时感觉像掌握了,一周后就没了。`teach` 通过理想难度来构建前者——提取练习、间隔、交错。知识在先,此时难度是敌人,因为它吃掉你理解所需的记忆容量;然后是技能,通过紧凑的反馈循环来操练,此时难度是工具。

有两样东西决定你被教到什么。**使命**——你要它的具体现实理由——为每节课奠基;没有它,课程会漂向抽象,没有任何东西能决定接下来学什么。从使命和学习记录出发,`teach` 在你的**最近发展区**内挑选下一课:难到需要费力气,又不至于远到学不动。

这也是技能会顶回去而不是一味顺从的原因。需要**智慧**——现实世界的判断力——的问题,会得到一个尝试性的答案,外加一个你可以去验证它的社群地址。测验是一道关卡,不是走形式:有用户报告说了句「非常感谢」,却被告诉操练还没结束。

## 课程、参考资料与组件

**课程**是单个自包含 HTML 文件,短到一口气能读完,紧扣使命,带来一个看得见的收获。它引用自己的来源,推荐一份值得自己去读的一手资料,并链接到兄弟课程和参考文档。

值得知道的分工:课程很少被重读,参考文档会。所以一节课的压缩精华——语法表、算法、体式序列、词汇表——属于 `reference/`,而不是埋在介绍它的那节课里。

课程由 `assets/` 里的**组件**搭建:样式表、测验组件、模拟器、图表助手。复用是默认。Agent 在撰写课程前会读 `assets/`,从已有的东西出发搭建,任何第二节课可能用得到的新东西都写成组件,而不是内联。共享样式表是每个工作区挣来的第一个组件;正是它让产出不是一堆一次性的东西。

## 常见问题

**它把文件放哪了?我的跑到 `~/.claude/skills` 里了。**
一个真实、未关闭的 bug([#377](https://github.com/mattpocock/skills/issues/377))。`SKILL.md` 同时把 `./` 用在两个不同的根上:`./MISSION-FORMAT.md` 及其同僚确实待在已安装技能里、挨着 `SKILL.md`,而 `./lessons/`、`./reference/`、`./learning-records/` 和 `./assets/` 本应位于你的目录。把第一种按技能安装目录解析的 Agent,会继续把第二种也解析到那里,于是把课程写进技能文件夹。在它之上继续搭建之前,先检查第一课落在哪;开始时显式指名目录,而不是指望「当前目录」被理解。

**我一直待在一个会话里,还是每课开新会话?**
三种做法都行——留在同一会话、在新会话里重新调用 `/teach`、或者在同一文件夹里开新会话。每课都是一次独立调用。文件夹才是连续性所在,对话不是。常见做法是在工作区里开新会话,说 `/teach next lesson for <topic>`。

**我怎么知道它没在教我编造的东西?**
光凭技能自己的话,你无从知道。你要去读一手资料。`teach` 还不够可靠,不能不加核对就信任,任何建立在 LLM 上的技能都一样。接地机制——`RESOURCES.md`、每课内的引用、每课一份推荐的一手资料——存在是为了让核验变便宜,而不是消除核验的必要。这种失败不是假设:有用户学 2×2 魔方时,拿到的是根本解不开的伪造步骤序列。这类案例的诊断清单是:模型、宿主环境、推理强度——以及来源是什么。风险在带精确记号的程序性领域最高,在输出可立即验证的地方最低,比如能直接运行的代码。

**测验的正确选项总是第一个。**
好几个人确认过,Sonnet、Opus 和 GLM 上都这样,至今未修复。`SKILL.md` 现在要求每个答案字数相同,这消灭了另一种暴露方式——正确答案曾经是唯一理由完整的那个——但对位置只字未提。有位贡献者测试了一个针对位置的指令级修法,报告正确答案在九节课里依然 33 次全部落在 A 槽([#335](https://github.com/mattpocock/skills/issues/335)),这指向 `assets/` 里一个洗牌测验组件才是真正的修法,而不是更好的措辞。在它上线之前,把答案位置当作无意义。你的 `assets/` 目录是你自己的,可以改,所以要求一个渲染时洗牌的组件是合法的本地修复。

**它假设我已经知道一些东西,还用了从未定义过的术语。**
最常见的实质性抱怨。没有评估步骤:`teach` 从使命和学习记录推断你的水平,而第一场会话里还没有学习记录。有用户在一个 wayfinder 流程里跑它,说得很直白——「它从不做问询来确立我的起点,所以对我的已知做了大量假设。」另有人报告课程依赖未定义的术语,还有一节课针对他们的硬件,讲了硬件能做什么,却从不说不能做什么。两件事有帮助:在第一条消息里说明你已有的知识和缺口;课程没讲到位时,大声纠正水平,因为纠正会成为学习记录,并引导下一课。显式的知识评估步骤是一个长期未决的功能请求([#725](https://github.com/mattpocock/skills/issues/725)),不是已发布的行为。

**它有间隔重复吗?知道什么时候停止教学吗?**
第一个没有,第二个不靠谱。间隔和交错是课程依之设计的原理,但没有任何东西安排复习,也没有 Anki 或日历集成——两者都是反复出现的请求。相关的缺口是退出标准:正如一位用户所说,`teach`「擅长做下一课,但不那么擅长知道什么时候该停下来,转向复习或真实练习。」如果你想要的是复习或操练而不是新内容,自己提出来;技能不会主动提议切换。

**它只对代码有用吗?**
不是,非代码用途是记录里更大的部分:韩语、日语敬语、钢琴、吉他、桌游设计、OpenSCAD、电影情节、Azure 和 CCNA 认证、大学考试,以及八岁十岁的孩子拿到关于密室逃脱和火蝾螈的可打印书。技能里没有任何东西是编程特有的——使命、资源、最近发展区和操练在任何领域都以同样方式运作。在代码范围内,被报告为最强用途的不是从零学一门语言,而是在陌生代码库或新团队的栈里找到方向。

**我该用什么模型跑它?**
没有标准答案,而且报告的差异很大。更高的[推理强度](https://www.aihero.dev/ai-coding-dictionary/effort)被报告能产出明显好于中等设置的课程。有用户把同一个技能放进 Copilot CLI 跑 Codex,只得到一张 30 行的 HTML 卡片,而 Claude Code 产出了完整课程。它在 Claude Cowork 里可以不改动地运行,取决于你的组织是否允许在那里添加技能。如果课程出来很单薄,先换模型、[宿主环境](https://www.aihero.dev/ai-coding-dictionary/harness)或推理强度,再考虑重写提示词。

## 效果如何判断

- 在空目录里,它做的第一件事是盘问你为什么想要这个,而不是直接产出课程。
- `RESOURCES.md` 在课程之前先填满,每课点名一份值得自己读的一手资料。
- 课程中的论断带外部链接。没有引用的课程是技能在凭记忆教学。
- 一节课占一次阅读,让你学会一件以前做不到的事。
- 在文件夹里开新会话说「下一课」,会继续课程而不是重开。
- `learning-records/` 在增长,课程不再重复教你已经证明会的东西。
- 课程看起来像一门课——它们链接 `assets/` 里的样式表,而不是各自带一份。
- 需要判断力的问题,会让你被指到一个论坛、subreddit 或课堂,而不只是给个答案。

## 在系统中的位置

`teach` 是一个**随时可用的独立工具**。它不是构建链里的一步,与工程流程不共享任何产物;它拥有自己的目录,在这个主题存续期间一直住在那里。

它唯一的真正邻居是 [handoff](https://aihero.dev/skills-handoff),经由 Matt 对「我在被盘问一个不懂的东西时该怎么办?」给出的答案的组成方式:不要停下问询去学习——`/handoff` 到一个教学工作区,在那边用 `/teach` 学会,再回来接着干。附近的替代是 [research](https://aihero.dev/skills-research),适合你想要的是一份带引用的文档而不是课程和记忆的情形。不确定哪个技能或流程合适时,[ask-matt](https://aihero.dev/skills-ask-matt) 会在整套里为你导航。
