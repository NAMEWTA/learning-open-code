## 功能说明

`grill-me` 会拿一个**模糊的想法**,通过反复提问帮你把它变成一串真实的决策。你不需要先想好完整计划——产出计划正是本次[会话](https://www.aihero.dev/ai-coding-dictionary/session)的目的。它按**轮次**提问:每一轮都会问整个**前沿**——所有前提条件已经满足的问题——所以你永远不会遇到一个依赖尚未听到的答案的问题。

它是**[无状态](https://www.aihero.dev/ai-coding-dictionary/stateless)**的。不写文件,也不留下工作区。它唯一留下的是你脑海中那个更清晰的想法。

## 何时使用

你通过输入 `/grill-me` 来调用它——[Agent](https://www.aihero.dev/ai-coding-dictionary/agent) 不会自己主动使用它。请在**全新的会话**中启动,而不是在一个 Agent 已经帮你写好的计划之上继续。

只要有了一个值得认真对待的想法——一个功能、一个产品方向、一个商业决策、一篇文章——就尽早用它,远在你想清楚它涉及什么之前。模糊不是等待的理由,它正是这个会话要吃掉的东西。如果你已经能把事情说得精确,那就不需要盘问了。

三个问询技能选哪个,取决于你面前有什么:

- **任何主题、任何地方**——`grill-me`。它不需要代码仓库,不写文件,主题也不必是代码。
- **要对着一个代码库问**——[grill-with-docs](https://aihero.dev/skills-grill-with-docs)。同样的面试,但它是[有状态](https://www.aihero.dev/ai-coding-dictionary/stateful)的:它会读你的代码,并把学到的记在 `CONTEXT.md` 和 ADR 里。
- **一次会话装不下**——[wayfinder](https://aihero.dev/skills-wayfinder)。它把工作量绘成地图,并在其中运行问询会话。

关闭[计划模式](https://www.aihero.dev/ai-coding-dictionary/agent-mode)。计划模式会推动 Agent 急着去产出计划,而这与保持追问恰恰相反。

## 这是对话,不是面试

技能负责提问,但**你**掌控范围。这一点很多人会忽略,也正是它把「把想法变成决策」的会话与「产出自信的废话」的会话区分开来。

失败模式是**被动**——连续四十个问题都答「同意、同意、同意」,最后得到一份 Agent 写的、你点头通过的方案。它会让你觉得很有成效,因为它很长。但实际上什么都没定下来,结果还带着一份它没挣来的确定感。

主动意味着掌控。问题低于你需要的精度时,把它推回去。范围漂移时,指出来。说「我不知道」时,就真的不知道。这个技能是来辅助工程师的,不是来替代工程师的:产出跟随的是你回答的质量,而不是提问的数量。

相反的错误也存在,但比较少见——在面试里待得太久,迟迟不进入代码。

## 能问出答案的和问不出来的

有些问题靠对话就能回答。另一些不能,再多的盘问也无济于事。

「用一张长表单还是三页纸?」和「这个交互应该是什么感觉?」就是**问不出来**的——它们需要有个东西来触发反应。遇到这种问题就停止盘问。用 [prototype](https://aihero.dev/skills-prototype) 做出一次性版本,看看效果,再回来一句话答完。

试图靠对话硬过问不出来的问题,正是会话失控膨胀的地方。Agent 不断换说法,你不断猜,范围为了填满不确定感而越涨越大。

## 效果如何判断

- 你会不同意某件事。一场没有你反驳的会话,是你本不需要的会话。
- 问题在少数几轮里成批到来,而不是一次一个地慢慢滴,而且后面的轮次明显建立在你之前的回答之上。
- 你最终走到一个没想到的地方,因为某个问题浮出了一项你一直在暗中做出的决策。
- 结束时,你能向一个不在场的人为每一个选择辩护。

## 常见问题

**我该预期多少问题,怎么知道它结束了?**
数轮数,别数问题。四个轮次里 46 个问题是一次普通会话。前沿清空时结束——每个分支都访问过,没有任何东西在沉默中被假定。

**它问了我两百个问题。哪里出了问题?**
通常是范围太大。先让 Agent 把工作拆小,再逐个盘问。很长的会话还会滑进**[迟钝区](https://www.aihero.dev/ai-coding-dictionary/smart-zone)**,此时[上下文窗口](https://www.aihero.dev/ai-coding-dictionary/context-window)几乎占满,问题质量开始下降。

**我能改回一次只问一个问题吗?**
可以。把它加进你的全局 `CLAUDE.md`:

```
When grilling, ask one question at a time.
```

**如果我真的不知道答案呢?**
直接说。「我不知道」是真实的答案;一个你答不上来的问题,通常是该去做原型而不是去猜的信号。

**写规格之前要开新会话吗?**
不用。这个会话的价值就在于你刚刚建立的[上下文](https://www.aihero.dev/ai-coding-dictionary/context)。把同一个对话直接交给 [to-spec](https://aihero.dev/skills-to-spec)。

**模型重要吗?**
比其他大多数技能都重要。问询倚赖[模型](https://www.aihero.dev/ai-coding-dictionary/model)自身对系统如何出错的判断力,所以给它你最好的模型。实现环节主要跟随上下文,用便宜一点的模型也没关系。

## 在系统中的位置

`grill-me` 是一个**随处可用的独立工具,任何东西都能盘问**。无状态正是它可移植的原因:没有仓库、没有工作区、没有配置,也不假定想法一定跟软件有关。有人拿它处理商业决策、文章、接下来该做什么——任何在脑子里安分不下来的事情。

这种可移植性正是它与 [grill-with-docs](https://aihero.dev/skills-grill-with-docs) 的全部区别:后者运行同样的面试,但会读一个代码库来对齐,并把学到的记成 `CONTEXT.md` 和 ADR。两者都建立在 [grilling](https://aihero.dev/skills-grilling) 原语之上;`grill-me` 是用户调用的前门,什么都不随身携带。

如果你盘问的对象确实要做成软件,可以把同一个对话交给 [to-spec](https://aihero.dev/skills-to-spec),继续进入构建流程——这是一个选项,不是这个技能的重点。不确定哪个流程适合时,[ask-matt](https://aihero.dev/skills-ask-matt) 会为你导航。
