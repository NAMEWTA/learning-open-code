# Wizard

**向导（wizard）** 是一个 bash 脚本，逐步引导人工用户完成一个手动流程——这类流程手工做起来繁琐，每次向 AI 重新解释同样繁琐。它打开每个 URL，准确说明要点击和复制什么，捕获这些值，把它们写入该去的位置（`.env`、GitHub secrets），在每个阶段确认，并显示还剩多少进度。它可以配置第三方服务、执行一次性迁移，或将项目从一种状态切换到另一种状态。

令人愉悦的用户体验已经由 [template.sh](template.sh) 解决了——剩余时间估算的进度显示、确认关卡、跨平台 URL 打开（包括 WSL）、隐藏的密钥输入、幂等的 `.env` 追加更新、`gh secret`/`gh variable` 写入，以及收尾摘要。**你的工作只在于界定流程范围并编写它的各个阶段。** `STAGES` 标记上方的库代码在每个向导中完全相同；这种一致性正是要点所在——永远不要手动编辑它。

向导默认是一次性的——为单次运行而构建，保存到临时目录或 `scripts/` 路径，任务完成后删除。只有当用户希望有一个可重复的设置流程并应保留在仓库中时，才提交它。

## 流程

### 1. 界定流程范围

梳理出人工用户必须执行的每个手动步骤，以及沿途捕获的每个值。先阅读仓库——不要直接冷提问：

- 对于设置流程：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置，以及 `.github/workflows/*`（其中每个 `secrets.*` / `vars.*` 引用，都是向导必须产出的值）。
- 对于迁移或转换：当前状态、目标状态，以及两者之间不可逆的操作。

然后向用户展示有序的阶段列表以及每个阶段产出的值，并确认——他们可以添加、删除或重新排序。

**完成标准：** 每个阶段都按顺序命名；对于每个捕获的值，你清楚 (a) 人工用户从哪里获取它，(b) 它写入哪里（`.env`、GitHub secret、两者都写、或无处可写——有些阶段只是纯操作），以及 (c) 它是密钥（隐藏输入）还是公开值。

### 2. 描绘每个阶段的路径

为每个阶段写出人工用户遵循的精确路径：打开哪个 URL、在那里做什么、某个值在哪里显示、它填入哪个变量——例如"Dashboard → Developers → API keys → Reveal test key → 复制"。当你并不确切知道当前 UI 或具体命令时，说明这一点并询问用户或查阅文档——永远不要编造可能不存在的步骤。

**完成标准：** 每个阶段都能对应到一份陌生人也能遵循的具体操作指引。

### 3. 编写向导

把 `template.sh` 复制到目标路径。用每个步骤一个 `stage` 替换示例阶段，按依赖顺序排列。使用库辅助函数——`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`——并将 `TOTAL_STAGES` 和 `TOTAL_MINUTES` 设置为诚实的估算值（这驱动剩余时间显示）。

守住模板设定的标准：在询问某个值之前先打开对应的 URL，任何密钥都使用 `ask_secret`，每个持久化的值都写入 `write_env`，`set_secret` 只用于 CI 真正需要的值，任何不可逆操作前都先 `confirm`。每个 `stage` 都会清屏，使屏幕上只显示当前步骤——让每个阶段只做一件聚焦的事，这样人工用户需要的信息就不会滚出屏幕。不要触碰标记上方的库代码。

### 4. 验证并交付

- `bash -n <script>`；如果可用，运行 `shellcheck`。
- `chmod +x <script>`。
- 不要自己端到端运行它——它会打开浏览器并阻塞等待人工输入。改为静态追踪：步骤 1 中确定的每个值都被捕获并落到步骤 1 所说明的位置，每个 `set_secret` 名称与 CI 中的 `secrets.*` 引用完全匹配。
- 告诉用户如何运行它。如果它是一个可重复的设置流程，提交它并在 README 中加上链接，这样下一个人运行脚本，而不是来问 AI。
